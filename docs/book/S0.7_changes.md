## How the edits were made

- python-docx 1.2.0. Each target paragraph was found by its **exact full text**, and the script checked that this text
  occurs exactly once in the whole document, tables included. Matching on the first occurrence was not used, because
  the table of contents repeats section titles. The script also checked the paragraph's complete list of runs before
  changing anything.
- Only the text of the named runs (`w:t`) was rewritten. Run properties were not touched, so italics, font sizes and
  theme fonts are kept. The two removed paragraphs were removed with `getparent().remove()`. No reversed iteration and
  no `addprevious` were used.
- After saving, `docs/book/extract_docx.py` extracted and compared both files (summary at the end).

- The row was kept, not deleted, because the pipeline still has this role. Only the tool changed.

**B3. Section 3.4, integration paragraph below Table 2**
- Before: "The curvature service produces directed Forman-Ricci scores for every edge using GeneralisedFormanRicci and
  escalates flagged subgraphs to GraphRicciCurvature for directed Ollivier-Ricci."
- After: "The curvature service produces directed Forman-Ricci scores for every edge using its own implementation and
  escalates flagged subgraphs to GraphRicciCurvature for directed Ollivier-Ricci."
- This paragraph also presented the package as part of the stack. The new wording is the same length as the old one,
  so section 4 still starts on a new page (see the layout check).

**B4. Non-academic links: two paragraphs removed**
- Removed: "GeneralisedFormanRicci: Forman Ricci curvature for simplicial complex." and
  "https://github.com/ExpectozJJ/GeneralisedFormanRicci".
- After this change, no text in the corrected copy mentions GeneralisedFormanRicci.

**Verification for B1–B4**
- The repository's `src/citecurv/curvature/forman_directed.py` (S1.4, commit `d37c785`) implements the Saucan et al.
  (2019) closed form. Its docstring states that no package implements this form.
- GraphRicciCurvature wheels from PyPI were read, not run (2026-10-31). In both 0.5.3.2 and 0.6.1,
  `FormanRicci.py` converts a directed input to an undirected graph and logs "Forman-Ricci curvature is not supported
  for directed graph yet" (0.5.3.2 lines 59–62, 0.6.1 lines 64–67). The claim that GraphRicciCurvature has no directed
  Forman therefore holds in both versions. Directed Ollivier-Ricci is present, through `predecessors` and `successors`
  neighbor distributions.
- GeneralisedFormanRicci on PyPI (latest 0.3, 2021-01-09) describes itself as "A class to compute the Generalised
  Forman-Ricci curvature for a Simplicial Complex from a given point cloud data". It is not a directed-graph package,
  so the original sentence was wrong.

**S1. Section 2.1.5, CurvGAD branch description**
- Before: "CurvGAD has two branches: one reconstructs node features, and the other reconstructs the curvature profile
  of the graph."
- After: "CurvGAD has two branches: one reconstructs the edge curvatures, and the other reconstructs graph structure

  (`https://raw.githubusercontent.com/karish-grover/curvgad/main/README.md`, fetched 2026-10-31; arXiv:2502.08605

  Ollivier-Ricci flow". The next sentence in the book ("The gap between predicted and observed curvature contributes to
  the per-node anomaly score.") was kept. The repository's `models/curvgad_detector.py`,
  `compute_combined_anomaly_scores`, combines a curvature reconstruction error, an adjacency error and a feature error

## Book statements that the July implementation work has since contradicted (listed only, not edited)

1. **Label counts.** The book says Retraction Watch holds "over 65,000 retracted papers" (1.1, 3.3 Data) and that the
   project gets "weak positive labels for over 65,000 known retracted papers" (2.2.1). The frozen snapshot of
   2026-07-06 has 70,771 records in total. The positive-label family (L12) is 14,896 records, or 14,842 unique DOIs
   (`data/labels/rwdb_counts.json`). The plan's L12 row still records 14,769 as of 2026-06-17. The positives are
   about 14.9K, not 65K, and the total is now above 70K.
2. **Retraction Watch access.** Section 2.2.1 says the dataset is "queryable through the Crossref REST API", and the
   non-academic links list "Crossref REST API. https://api.crossref.org/". The project downloads the CSV from Crossref's
   GitLab repository (`gitlab.com/crossref/retraction-watch-data`, L9 and S0.6). The old Crossref Labs endpoint no
   longer works. "Retraction Watch (via Crossref)" in Table 2 is still accurate.
3. **GraphRicciCurvature version.** The book names no version. The plan (L5, `configs/pins.md`) pins 0.5.3.2 and calls
   the project dormant upstream. PyPI now has 0.5.4 (2026-08-13), 0.6.0 and 0.6.1 (both 2026-08-24). Neither 0.5.3.2
   nor 0.6.1 has directed Forman-Ricci (checked in the source), so section 2.2.2 holds either way. Which version to pin
   is for the integrator to decide.
4. **Graph scale.** Sections 1.2 and 3.3 speak of "hundreds of millions of edges", and 3.3 Data uses "over 250 million
   works" for the positive-class rate. L11 limits evaluation to a retraction-dense slice of about 300K works and 2–3M
   edges. The book's statements describe the full OpenAlex graph, not the evaluated graph.
5. **OpenAlex access.** The book calls it a free public API. L7 adds that it is used with a free API key that comes
   with $1/day of credit.
6. **SPECTER2 link.** The non-academic link points to `huggingface.co/allenai/specter2`, which is the proximity adapter
   (L6). The base model is `allenai/specter2_base`.
7. **Baselines.** Section 2.2.5 names CurvGAD and PyGOD only. L17 adds the project's own TGN without curvature, an
   XGBoost classical-ML tier and a statistical tier. The flow chart (step 5) does mention three tiers.
8. **Determinism wording.** NFR 4 (3.1.2) asks for "identical outputs". Book 4.2.2 (iii) and the plan allow a fixed
   tolerance (1e-6).
